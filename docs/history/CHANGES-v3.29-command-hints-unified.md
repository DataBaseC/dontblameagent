# v3.29 · 命令类工具统一口径（`shell` / `job` / `edit_file`）

> v3.28 只改了 `run_command`。这一版把它定下的**报告约定**与**自救提示**推广到
> 同一族的其它工具 —— 一套映射只写一处（`CommandHints`），改一次全都跟着变。

---

## 一、抽出的「单一来源」：`CommandHints`

```
src/AgentFramework.Tools/CommandHints.cs
```

约定（写进注释，代码只此一处）：

1. 退出码非零**不是工具失败** —— 那是命令跑完后的结论（编译失败 / 测试不过 / grep 无匹配都可能是非零）；
2. 只有「命令根本没起来」（`exit=-1` 且零输出）、超时、取消才算工具失败；
3. 失败时**必须**给「下一步怎么走」—— 否则模型只会原样重试到天荒地老；
4. 报告头行够用就好：**非默认值才回显**（正常路径不塞长文本）。

对外三个函数：`SelfRescue(exitCode)`（可识别失败模式 → 一行自救；认不出返回 null 不加噪音）、
`TimeoutRescue(persistentShell)`（超时三步）、`TimeoutSuffix(actual, default)`（非默认才回显）。
`run_command` 同步改为共用它（删掉本地那份私有实现）。

## 二、`shell`（持久会话）—— 同一个毛病

**改前**：`return outcome.ExitCode == 0 ? ToolResult.Ok(text) : ToolResult.Fail(text);`
—— 与 `run_command` 一模一样：非零退出被包成失败，模型看到 `ERROR:` 前缀。

**改后**：

| 项 | 变化 |
|---|---|
| 非零退出 | 改为 **Ok**（退出码如实写在报告第一行），并对 127 / 126 / 9009 补 `[hint]` |
| 超时 | 仍是 Fail（真没跑完），但补**三步自救**（对持久 shell 特化：直接劝 `run_in_background`，不再劝它「改用 shell」） |
| `timeout` | 非默认时回显 `timeout=Ns`（与 `run_command` 同口径） |

## 三、`job` —— 错了要有出路

**改前**：`作业不存在：job-xxx` —— 模型只能靠猜重试。

**改后**：`作业不存在：job-xxx；用 action=list 看现有作业，再拿对 id 重试`（`status` / `output` / `kill` 三处统一）。
另在描述里点明「**退出码非零只是命令的结论，不是本工具失败**」。

## 四、`edit_file` —— 失败要指路

| 情形 | 改前 | 改后 |
|---|---|---|
| 文件不存在 | `文件不存在：x.md` | `文件不存在：x.md（用 list_dir 确认路径；要新建文件请用 write_file）` |
| 找不到 `old_string` | 「请先 read_file 读取该处…」 | 编号自救：① 用 read_file / read_lines 读该处、连缩进复制；② **若这处刚被别的编辑动过，重读一次再改** |
| `old_string` 出现多次 | 「首次约在第 N 行」 | **列出每一处的行号**（最多 5 个）：「第 3 / 5 / 12 行」+ 两条自救（扩写上下文 / `replace_all=true`） |

> 列行号的理由：改错地方比改不动更贵。模型看到全部命中位置，一眼就知道该扩写哪一段上下文。

## 五、验证

`VerifyTools` 66 → **73**（+7）：

| 断言 | 钉住什么 |
|---|---|
| `shell` 非零退出 → `Success == true` | 与 `run_command` 同口径，不再伪装成工具失败 |
| `shell` 命令不存在 → 报告含 `[hint]` | 自救提示在持久会话里同样生效 |
| `job` id 打错 → 错误含 `action=list` | 错了有出路 |
| `edit_file` 文件不存在 → 错误含 `write_file` | 失败指路 |
| `edit_file` 多处匹配 → 错误含 `第 3 / 5 行` | 列出每一处行号 |
| `edit_file` 找不到原文 → 错误含 `自救` | 编号自救文案在位 |
| `replace_all=true` → `已替换 2 处` | 成功路径不受影响（回归） |

全量：**20 套 / 1313 项 / 0 失败**（VerifyTools 66 → 73）。

## 六、一个顺带发现（未改）

在持久 shell 里跑**内建 `exit`** 会**终结会话**（返回 `exit=-1` 并触发重建）——
行为本身是对的（工具已按「会话已重建」如实标注），但模型可能误以为「命令没能启动」。
当前不改：`exit` 在持久会话里本就罕见，且重建行为如实可见；若将来真被踩到，再给它一条专门提示。
