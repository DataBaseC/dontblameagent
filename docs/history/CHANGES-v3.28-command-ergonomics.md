# v3.28 · `run_command` 调用体验打磨（让模型调得顺）

> 主题：工具再强，模型**一次调不对**就等于没有。这一版只做一件事 ——
> 把 `run_command` 从「能跑」改成「**好调、错了能自救**」。

---

## 一、核心修正：退出码非零 ≠ 工具失败

**现象**：`run_command` 在 `exit != 0` 时返回 `ToolResult.Fail(...)`。

主循环的注入写法是：

```csharp
Content = result.Success ? result.Output : $"ERROR: {result.Error}";
```

于是命令输出被套上 `ERROR:` 前缀 —— **编译失败、测试不过、`grep` 无匹配**（全都天然是非零退出码）
在模型眼里都成了「工具坏了 / 我被拒绝了」，而不是「去看输出里到底说了什么」。
模型于是容易改道、反复重试，或者干脆放弃。

**修正**：只有**命令根本没起来**（ProcessRunner 的固定返回形状：`exit=-1` 且零输出）才算工具失败。
其余一律「命令跑完了」，如实交回 stdout / stderr / 退出码：

| 情形 | 从前 | 现在 |
|---|---|---|
| `exit=0` | Ok | Ok |
| `exit=1`（编译失败 / 测试不过 / grep 无匹配） | **Fail → `ERROR:` 前缀** | **Ok**（退出码在报告第一行） |
| `exit=127`（命令不存在） | Fail | **Ok** + 一行自救提示 |
| 超时 | Fail | Fail（真没跑完）+ 自救提示 |
| 取消 | Fail | Fail |
| 命令未能启动（`exit=-1` 零输出） | Fail | Fail |

## 二、补两个参数（对齐 `shell` 的同名能力）

| 参数 | 作用 |
|---|---|
| `timeout`（秒） | 长构建 / 长测试自救。**夹在运维硬上限内**（`CommandMaxTimeoutSeconds`，默认 600）—— 上限进配置、当前次取值进参数 |
| `description` | 一句话说明这条命令在干什么，进报告（审计与追溯；与 `shell` 一致） |

报告里**只在该值非默认时**回显 `timeout=Ns` —— 正常路径不加长文本（与沙箱降级备注同一纪律）。

## 三、失败时的「怎么自救」

**超时**（真没跑完）：

```
命令超时（30s），已连同子孙进程终止（沙箱 process · shell bash）。
自救：① 加 timeout 参数（上限由运维设定）；② 长任务改用 shell 的 run_in_background 或 job 工具放后台跑；
③ 先缩小范围（只跑失败的用例 / 只构建目标工程）。
```

**非零退出**：只对**可识别**的模式补一行 `[hint]`，认不出的不加噪音：

| 退出码 | 提示 |
|---|---|
| `127` / `9009`（Windows） | 命令不存在。检查拼写，或先 `which` / `where` 确认它装在哪 |
| `126` | 命令不可执行。检查文件权限（POSIX 可 `chmod +x`） |
| `-1` | 命令未能启动。确认可执行文件存在、路径正确、shell 可用 |

## 四、工具描述重写（选对工具）

`run_command` 的 description 从前**只字未提** `shell` / `job`，而「要保留状态就用 shell」这条指引
只写在 `shell` 那一侧 —— 模型先看到 `run_command` 就一路用它，于是 `cd` / `export` / venv 反复失效。
现在开头就点明：

- **每次都是新进程**（cd / export / 虚拟环境跨调用不保留）→ 要保留请用 `shell`；
- 长任务别干等 → 加 `timeout`，或改用 `shell` / `job` 放后台；
- 退出码非零仍会如实返回输出，**请读输出判断，别当成工具故障**。

## 五、验证

`VerifyTools` 新增断言（§2b）：

| 断言 | 钉住什么 |
|---|---|
| `exit=3` → `Success == true` | 非零退出不伪装成工具失败 |
| 命令不存在 → 报告含 `[hint]` | 错了能自救 |
| 超时错误文案含 `timeout 参数` + `run_in_background` | 超时不再是死路 |
| `timeout=99999` → 报告 `timeout=600s` | 上限夹逼（模型管不了上限） |
| `timeout=45` → 报告 `timeout=45s` | 参数生效且如实回显 |
| 带 `description` → 报告含 `# …` | 审计信息真的进了报告 |
| 不传 timeout → 报告不含 `timeout=` | 正常路径不塞噪音 |

全量：**20 套 / 1306 项 / 0 失败**（VerifyTools 59 → 66）。

## 六、没做（留待真实需求）

- **`cwd` 参数**：目前只能 `cd x && cmd`（可接受；真要加须走工作区路径校验）。
- **`run_command` 的后台**：后台走 `shell` / `job` 两个入口已够；再给第三个入口只会让选择更乱。
- **Windows 的 `pwsh` 持久通道**：见 `docs/GAP-vs-dsh.md` 的「部分」档。
