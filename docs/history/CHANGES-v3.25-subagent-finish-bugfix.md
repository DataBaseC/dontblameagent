## 一、补齐的三项

| 项 | 做法 |
|---|---|
| **抢占式中断** | `Post(id, text, interrupt: true)`：作废它**当前这一轮**，立刻改用新指令重跑。实现是「每轮一个轮级 CTS（链接到终结 CTS）」—— `Stop` 取消终结 CTS、抢占只取消轮级 CTS，主循环据此区分「接下来」与「就此收场」。工具面 `subagent` 的 `message` 加 `interrupt` 参数 |
| **派生深度闸** | `handle.Depth`（顶层会话派出的 = 1）+ `HostOptions.SubAgentMaxDepth`（默认 2）。超出时**如实拒绝**（不是静默截断）。没有闸的话，子 Agent 可以无限往下派 —— 那是一条悄悄烧钱的路径 |
| **界面面板** | 侧栏新增「子 Agent」区块（只在真的有子 Agent 时出现）：状态 · 回合数 · 前后台 · 任务摘要，3 秒一轮拉 `/api/subagents`。窗口尺寸/布局沿用侧栏既有样式 |

## 二、抓到并修掉的真缺陷（第一批 8 个）

### 1. 【并发正确性】多个子 Agent 并发回报同一父会话 → 内存事件表乱序

落盘（`JsonlEventLog.Append` 在自己的锁里分配 Seq）与入表（`SessionRuntime.Track`）是**两把锁、两步**。
并发时完全可能出现「T1 先拿到 seq 5、T2 后拿到 seq 6，但 T2 先入表」——
表一乱序，投影就会把 `completed` 排到它对应的 `requested` **前面**。

修：`Track` 改为**按 Seq 有序插入**（顺序追加仍是 O(1)，只在真交错时才退化）。
守门断言：8 个子 Agent 并发完成后，父会话事件表 Seq 严格单调。
> 这是 v3.24「并行派发」引入的新并发面 —— 旧代码只有一条留痕路径，撞不上。

### 2. 子 Agent 会话混进人的会话列表

`ListSessions()` 枚举 sessionsDir 下所有 `*.jsonl` —— 包括每次派工产生的 `sub-*.jsonl`。
于是**每派一次工，人的会话列表里就多一条空会话**。
修：`SubAgentRegistry.ChildIdPrefix` 作为**单一来源**，生成与会话列表过滤都用它。

### 3. 父会话不存在时，错从「留痕」深处冒出来

`SpawnAsync` 先派发、后留痕（`EmitToSessionAsync`）；父会话已关闭时，
异常会以「会话不存在」的形式从深处抛出 —— 既没指向参数，调用方也无从修。
修：派发前**前置检查**父会话是否活着，错得清楚一点。

### 4. 宿主关停不设退休、不等回合（**外部审查 P1-2**，一直没修）

`MarkRetired()` / `WaitIdleAsync()` 建好就摆在那儿，**零生产调用点**。
后果：关停时若有回合在跑，那个回合的收尾会撞上已 Dispose 的日志与信号量。
「防线建好却不接线，比没有防线更危险 —— 读代码的人以为关停是安全的。」
修：`DisposeAsync` 首行 `MarkRetired()`（此后新回合一律拒绝），随后对每个会话**等回合闸 ≤5 秒**再拆（等不到也不硬等，不把关闭流程卡死）。

### 5~8. 小的

- **关停只 cancel 不等**：新增 `SubAgentRegistry.DrainAsync(3s)`，避免子 Agent 的收尾与「回收会话」并发。
- **子 Agent 收尾未保护**：收尾段整体 try/catch —— 收尾失败不该变成「无人观察的任务异常」。
- **`subagent wait` 没有超时上限**：模型误传一个巨大值会把回合挂到天荒地老。夹取到 600 秒（上限进代码、取值进参数，与 `run_command` 同一思路）。
- **`AtomicFile` 写入失败/取消时残留临时文件**：把「写入」本身也纳入 try —— 磁盘满 / 取消不再留下半截 `.tmp-xxxx`。

### 9~10. 第二轮排查（关停与后台作业）

上面 8 处修完、重跑全量之后，沿「**关停之后还有谁在动**」这条线再扫了一遍，又抓到两处：

- **宿主关停不叫停后台作业**：checkpoint 摘要 / 锚点、进化 Dream / Distill 都是
  `_ = Task.Run(..., CancellationToken.None)` 起的 fire-and-forget，**不随宿主生命周期走** ——
  宿主拆掉之后它们还在往盘上写（检查点文件 / 记忆 / 技能草稿），留下半截文件与无人观察的异常。
  修：宿主加**生命周期取消源** `_lifetime` + 后台作业登记簿（`TrackBackground`），上列作业一律挂
  `LifetimeToken` 并登记；`DisposeAsync` 在停子 Agent 之后 `Cancel()` + **有界等待 3 秒**
  （等不到不硬等，同「等回合闸」纪律）。
  守门断言：一个会一直挂到被取消的 checkpoint writer，宿主关闭后必须收到取消（改前它拿的是
  `CancellationToken.None`，永远收不到）。
- **子 Agent 启动 / 异常没有结局**：`RunAsync` 里的 `OpenSession` 落在 try **之外** ——
  它一抛（宿主正在关停、会话表已被收走），条目会**永远卡在 Running**，而后台派发的路径
  没人 await 这个任务，异常也就无人观察。修：把它纳入 try，异常统一落成 `Failed` + 摘要。
  守门断言：模型每次调用都抛时，子 Agent 条目必须收场为 `Failed`（不卡 Running）。
