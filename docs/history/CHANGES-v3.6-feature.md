# v3.6 修复与新增（四项实测反馈 + 一项边界澄清）

> 来源：主人实测反馈。
> 纪律：每条都先在沙盒里**复现**（起真宿主抓 SSE 帧 / 用 jsdom 真跑界面），修完再回测；
> 12 个验证工程 **760 项 0 失败**。

---

## 一、② 新建会话「聊着聊着消息不对」

**现象**：新建会话（闲聊模式也一样）发消息，用户自己的消息不显示、助手回复全串进同一个气泡，
看起来就是「旧消息没了」。

**复现**（沙盒起真宿主 + curl 抓 SSE）：新建会话后连发两条，SSE 里**只有 `delta` 与 `turn-ended`**，
一条事件帧（`user-message` / `assistant-message` / `model-usage` / `tool-call-*`）都没有；
而**启动时的默认会话**帧是全的 —— 所以只有「新开出来的会话」坏。

**根因**：`HostModule.OpenSession` 里，`relayToUi` 只决定 delta 推不推
（`OnTextDelta = relayToUi ? … : null`），事件中继仍要求调用方**显式传 `onEvent`**。
`/api/sessions/new` 只传了 `relayToUi: true`、没传 `onEvent` —— 事件进不了内存表之外的任何出口。
（默认会话走 `GetOrOpenSession`，那儿传全了，所以一直没暴露。）

**修**：`relayToUi == true` 且没给 `onEvent` 时默认接上 `EventRelay` ——
「这个会话要在界面上显形」这一个开关同时管 delta 与事件，不再靠调用方记得传参数。

**回测**：新建会话的每条消息，SSE 帧变成
`user-message → delta → model-usage → assistant-message → turn-ended`；
jsdom 真跑界面，消息正确分成 user / assistant 气泡。

## 二、③ 工具调用失败后「卡在执行中」、发送键不回来

**现象**：工具调用失败（回合很快收尾）后，界面停在「思考中…」，发送键仍是「■ 停止」，
要手动再点一下才复位。

**根因**：回合跑得比 202 响应还快时，`turn-ended` 先到 → 前端已复位；
随后 `/api/send` 的 202 才回来 → 前端**无条件** `setTurnRunning(true)` →
已经结束的回合被按回「运行中」，按钮再也回不来。

**修**：`turn-ended` 帧带上 `turnId`；前端记下「已结束的 turnId」，
202 回来时若这个回合已经结束，就**不再**置运行中。前端不再靠猜。

**回测**（jsdom：202 延迟 200ms、turn-ended 先发）：修复前发送键停在「■ 停止」，
修复后回到「发送」。

## 三、④ 启动器不再强制多开一个浏览器页（改成开关）

`Launcher` 启动时会无条件自动打开浏览器显示管理页。现在：

- 默认行为不变（照旧自动打开 —— 第一次用的人不会找不到页面）；
- 管理页上多了一行「启动时自动打开浏览器：开 / 关」，**持久化**到
  `profiles/launcher-settings.json`（跟着档案目录走）；
- `--open` / `--no-open` 可只对本次强制覆盖。

## 四、① 新建会话可以「浏览…」挑项目目录（可新建文件夹）

原来只能在输入框手打绝对路径。现在弹层多一个「浏览…」，打开目录浏览弹窗：
进子目录 / 上一级 / 主目录 / **新建文件夹** / 「就用这个目录」。

目录内容由本地服务给（`GET /api/fs/dirs`）—— 浏览器出于安全拿不到本地绝对路径
（`showDirectoryPicker` 只给句柄），而项目目录必须落成一个真实路径，只能由本地服务如实列。
「新建文件夹」（`POST /api/fs/mkdir`）只收**单层目录名**（含路径分隔符或 `.` / `..` 一律拒）。

浏览范围＝整台机器（主人明确要「自己挑任意位置」）。服务只监听回环地址，
写操作都过 Origin 同源校验。

## 五、边界澄清：**读放开、写圈死**

主人要求：对话中的单个项目，**读**可以到硬盘任意目录，**写**只能落在本项目工作区。

`WorkspacePath.TryResolve` 因此分成两条边界（`forWrite`）：

- 读（`read_file` / `list_dir`）：默认不受工作区约束（绝对路径、`../` 都放行）；
- 写（`write_file`）：仍必须**真实**落在工作区内 —— 保留带结尾分隔符的比较与符号链接穿透，
  经链接绕出去的写照样被拒。

开关 `ToolkitOptions.AllowReadOutsideWorkspace`（默认 `true`）：置 `false` 就退回
v3.5 之前「读写都锁在工作区内」的旧边界。

**测试相应调整**（3 条断言的语义反转，不是放宽门槛）：

- 「读越界路径被拒」→「★ 读可以越出工作区（读得到）」；
- 「经符号链接读区外文件被拒」→「★ 经符号链接读区外文件被放行（读不受限）」；
- 「项目目录外的文件同样被拒」→「★ 读仍不受限」，并**新增**
  「★ 项目目录外的写被拒」与「★ 项目目录外的文件确实没被改写」。

**写侧的边界断言（含符号链接穿透）一条没动** —— 那仍是硬约束。
