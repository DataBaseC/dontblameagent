# 计划 · 工具包与暴露面（Toolset & Exposure）

> 目标：让「装了什么」与「这一轮给模型看什么」**解耦**——
> 装得多不等于负担重；真实干活时可以**有选择地开**。

## 0. 为什么要做（先算账）

| 项 | 现状 |
|---|---|
| 已注册工具 | 31 个（官方 19 + 基石 12） |
| 工具定义体积 | Description 2,957 字符 + Schema 7,066 字符 |
| 每轮固定开销 | **≈ 10k 字符 ≈ 3k token** |

两条行业实测的线（Anthropic 口径）：

- **30–50 个工具是准确率拐点**：过了这条线，模型挑对工具的能力开始下滑。我们已经在线上；
- 多服务器 MCP 配置（GitHub / Slack / Sentry / Grafana / Splunk）**光工具定义 55k token**，还没开始干活。
  真接了 MCP，这一条会立刻命中。

**病根不在"插件太多"，而在：装载与暴露被绑成了一个开关。**

> 插件一装 → 工具立刻全暴露；可见性只有「全开 / 全关 / 手列 31 个工具名」三种写法。

## 1. 目标与非目标

**做**

- 引入**工具包（Toolset）**：最小选择单位从「工具名」变成「包」；
- **装载 / 暴露解耦**：插件照常装，暴露由「基础包 ∩ 启用包」决定；
- 运行期可按包开关（**人**在界面点、**agent** 用工具调），每轮现取、不必重启；
- 为后续两件事**预留位置**（本次不做，但数据结构先留）：
  **延迟包**（deferred，不进 schema 只进索引）与 **Tool Search**（阈值触发）；
- **默认行为不变**：不配置就等于全部开启（零回归）。

**不做（本次）**

- Tool Search 本体（下一步）；MCP 通道（再下一步）；
- 按工具名的细粒度权限（包是"够用的粒度"，细到这个层级只会没人用）。

## 2. 结构：三层递减

```
第一层  工具包（Toolset）         ← 本次做
        包 = 一个标签；工具自报所属包；插件在清单里声明
        选择单位：31 个工具名 → 4~6 个包

第二层  常驻 / 延迟（deferred）    ← 本次只留字段
        常驻包进 schema；延迟包只进索引（一行一句话）

第三层  Tool Search              ← 下一步
        模型按需把延迟工具的完整 schema 拉进上下文
        阈值触发：工具数 ≤ 30 时不启用（多一轮交互不划算）
```

## 3. 数据与接口设计

### 3.1 工具侧（契约）

```csharp
/// 工具自报所属包。不实现 = 落在默认包（注册来源同名包）。
public interface IToolWithToolset : ITool
{
    string Toolset { get; }
}
```

### 3.2 包描述（内核）

```csharp
public sealed class ToolsetDescriptor
{
    public string Id { get; set; }            // "core" / "files" / "devkit" / "mcp:github"
    public string Name { get; set; }          // 显示名
    public string? Description { get; set; }
    public bool Eager { get; set; }           // 常驻（进 schema）。false = 延迟包
    public string Source { get; set; }        // 谁提供的：core / 插件 id / "mcp:<server>"
}
```

- 官方工具的包在代码里声明（`CoreModule` 建包并登记描述）；
- 插件在 `plugin.json` 里声明 `"toolsets": {...}`，内核装载时自动登记（Source = 插件 id）；
- 未声明包的工具 → 落进与**注册来源**同名的包（于是老插件不改清单也自然成包）。

### 3.3 暴露面计算（宿主）

```
候选 = 全部已注册工具
  ∩ 基础包（模式声明的包集；null = 不限）        ← 新增 ModeProfile.AllowedToolsets
  ∩ 已启用包（= 全部包 − 本次会话关掉的包）      ← 默认全启用
  ∩ 模式精确白名单（老语义，保留兼容）
  ∩ 已启用技能的工具白名单（老语义，保留）
再按包的 Eager 分流：常驻 → schema；延迟 → 索引（本次：全部视为常驻）
```

**默认全开**是关键选择：第一步只加能力、不改行为，回归风险为零；
用户真觉得重了，再去关。

### 3.4 开关的三个入口

| 谁 | 怎么开 | 落点 |
|---|---|---|
| 人 | 界面上一排「包」开关 | `GET /api/toolsets` + `POST /api/toolsets/toggle` |
| agent | 两个工具：`toolsets`（看）/ `use_toolset`（开、关） | 官方工具，注册在 `meta` 包 |
| 配置 | `agent.json` 的 `disabledToolsets`，或模式里的 `allowedToolsets` | `HostOptions` |

开关状态是**会话级运行期状态**（像技能那样）：每轮现取，下一轮就生效，不重启、不重装。

## 4. 实施步骤（四步走，每步独立可验）

| 步 | 内容 | 验收 |
|---|---|---|
| **① 工具包（本次）** | 契约 + 内核登记 + 暴露面计算 + 三个开关入口 + 官方/基石工具的包归属 | 新增 `VerifyToolsets`：关一个包 → 它的工具立刻消失、其他包不受影响；默认全开与旧行为一致 |
| **② 统一暴露策略（本次）** | 模式 `AllowedToolsets` 落地；技能与包的关系写清（技能白名单 ∩ 包） | 模式层面：闲聊模式 `[]`、工作模式 `null` 的现有语义不回归 |
| **③ MCP 通道** | 子进程 + MCP 协议兼容；工具自动进 `mcp:<server>` 包，**默认延迟 + 按 server 开关**，server 首次用到才启动 | 接一个只读 MCP server：初始 schema 增量 ≈ 0（延迟生效） |
| **④ Tool Search** | `tool_search` 工具 + 索引；阈值（>30）才启用 | 工具数 100 时，定义开销下降 ≥ 80% |

顺序的理由：③ 的 MCP 工具必须落在包与延迟机制上，反过来做必然返工。

## 5. 兼容与迁移

- `ModeProfile.AllowedTools`（逐工具名白名单）**原样保留**，与包取交集 —— 自定义模式不受影响；
- 现存插件清单不写 `toolsets` 也能工作（按注册来源自动成包）；
- 默认不关任何包 → 现有验证工程（845 项）应当**全绿不动**；
- 唯一可见变化：`run_command`… 不受影响；界面多一排开关；`/api/status` 多一个 `toolsets` 段。

## 6. 风险

| 风险 | 应对 |
|---|---|
| 包切得太粗（等于没切） | 先按「来源 + 能力域」切：core / files / search / memory / web / plan / meta / devkit / writing-kit |
| 包切得太细（又变成记 31 个东西） | 目标 4~6 个常用包；包列表只显示「有工具且可关」的 |
| agent 自己把工具关得没法干活 | `core` 包**不可关**（读文件、写文件、列目录、ask_user 这些不给关；`run_command` 在 `exec` 包，可关） |
| 开关状态丢失 | 会话级状态 + 事件流留痕（与技能同一套做法） |
